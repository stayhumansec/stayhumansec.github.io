The short version: there's nothing to opt out of.

Every page on this site opens with a boot sequence that checks for trackers, ad scripts, and cookies — and finds zero, every time, because there genuinely aren't any. This page is the longer, plainer explanation of exactly what that means and what the few opt-in tools on this site actually do.

No analytics, no ad scripts, no cookies

This site doesn't run Google Analytics, Meta Pixel, or anything like it. There's no ad network, no third-party script loading in the background, and no cookie banner — because there's nothing here that needs your consent to run. Fonts (Sora, IBM Plex Mono) are self-hosted from this site's own /fonts folder specifically so loading a page never pings a font CDN either.

Reading posts, News, or on(my).mind doesn't send anything anywhere

Browsing, searching (the local keyword search on Search the Archive), and reading articles is just your browser fetching static files from this site — the same as reading a plain webpage. Nothing about what you read, search, or click is recorded, because there's no backend to record it to. This is a static site with no server-side code at all.

A few tools save things — only in your own browser

Password Coach, the 2FA Recovery Kit Builder, and the "already read" markers on the posts listing all use your browser's own localStorage to remember things between visits (a saved API key, your recovery kit entries, which posts you've opened). None of that ever leaves your device — it's not sent to us or anyone else, and clearing your browser data clears it instantly and completely.

The optional AI features are bring-your-own-key, direct to Anthropic

Search the Archive and Password Coach both offer an optional AI layer if you add your own Anthropic API key. When you use it, your question and your key go directly from your browser to Anthropic's API — never through a server we run, because we don't run one. Your key is stored only in your browser's localStorage. Everything on both pages keeps working normally if you never add a key.

Breach Exposure Check is the one tool that sends anything at all

Checking a password against known breaches works by hashing it (SHA-1) in your browser, then sending only the first 5 characters of that hash to the Have I Been Pwned API — a k-anonymity technique that means neither we nor HIBP ever see your actual password, or even your full hash. Full details are on the Breach Exposure Check page itself.

Hosting-level logs are outside our control

This site is hosted on GitHub Pages, like any static site. GitHub's servers see the same basic connection information (IP address, requested file) that any web host sees for any request on the internet — that's standard infrastructure logging, not something this site adds, chooses, or has access to. We don't run our own analytics on top of it.

If something here changes

If a future tool needs to work differently than described above, this page gets updated the same day that tool ships — not after the fact. There's no mailing list to notify because there's no account system to notify it through; checking back here is the way to know.
